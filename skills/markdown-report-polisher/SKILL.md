# Markdown 报告润色 Skill

## 工作流程

1. 先阅读原始 Markdown，不要直接重写。
2. 如果用户提供了文件，先运行 `scripts/inspect_markdown_report.py <path>` 检查结构问题。
3. 如果用户要求完整改写、管理层口吻或更严格的报告格式，读取 `references/report-style.md`。
4. 保留原文事实、日期、数字、负责人姓名和开放问题。
5. 除非用户要求分析，否则只改写报告正文。
6. 如果缺少必要事实，在结尾简短列出仍需补充的信息。

## 推荐结构

除非原文已有更强的本地格式约定，优先使用下面的结构：

```markdown
# <报告标题>

## 摘要
<用 3 到 5 条要点，或一个短段落说明当前状态、需要的决策和截止时间。>

## 进展
- <按结果归类已经完成或正在推进的工作。>

## 风险
- <风险、影响、负责人、缓解措施。>

## 决策
- <已经做出的决策，或需要谁在什么时候做什么决策。>

## 行动项
- [ ] <负责人> - <动作> - <截止日期>
```

## 编辑规则

- 保持用户原意，不编造状态、负责人、日期或指标。
- 只有在原文包含负责人和动作时，才把模糊任务改成复选框行动项。
- 缺少负责人或日期时写 `TBD`，不要猜测。
- 删除重复状态、空泛表达和无信息量的铺垫。
- 在上下文允许时，用具体名词和动词替代“处理一下”“跟进一下”等模糊表达。
- 标题层级尽量不超过三级，除非原文已有必要的更深结构。
