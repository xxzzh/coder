项目定位
01 · WHAT IT IS

作品实现了什么

资料入库

支持 Word、PDF、Excel、Markdown、文本和扫描件资料入库。

证据检索

把资料切成可追溯片段，建立本地全文索引和向量索引。

问答输出

用户自然语言提问，系统返回答案、来源和检索状态。

质量治理

识别 OCR、图表、低信息片段等风险，避免静默进入可信答案。

不是把大模型接到文件上，而是把本地资料治理成可验证的知识资产。

当前痛点
02 · PAIN POINTS

原流程的问题：慢、散、难核验

资料分散

Excel、PDF、Word、扫描件和个人经验分布在不同目录，查找链路长。

答案无证据

很多结论依赖口头经验或截图，事后难以追溯到具体资料片段。

版本不清

测试计划、门限和流程存在版本变化，人工查找容易误用旧资料。

复杂资料漏看

合并单元格、流程图、扫描页和图表标签容易被普通搜索忽略。

专家重复答疑

同类测试项、工具、门限问题反复询问，经验没有沉淀。

新人学习成本高

新人理解站位、测试项、门限和流程依赖老员工解释。

系统架构
05 · ARCHITECTURE

轻量本地 RAG 架构

入口层

Web UI、命令行、一键菜单、健康检查。

应用编排层

问题解析、查询规范化、领域路由、本地优先。

检索与证据层

SQLite FTS5、hash n-gram embedding、LSH 候选、关键词覆盖、混合重排、引用校验。

知识治理层

多格式抽取、OCR、语义分块、去重、质量报告、增量索引、复核标记。

模型与存储层

SQLite 本地库，兼容 DeepSeek、OpenAI-compatible API，也支持无 API 本地模式。

横向治理

缓存、日志脱敏、异常降级、互斥锁、索引状态、质量报表。

纵向链路负责从文件入库到问答输出；横向治理负责让系统稳定、可信、可维护。

核心技术
08 · HYBRID RETRIEVAL

三路召回 + 混合重排

01

FTS5 全文检索

擅长编号、工具名、站位、测试项、门限等精确关键词。

02

本地向量召回

hash n-gram 384 维稀疏 embedding，用于相似片段召回。

03

LIKE 兜底召回

在 FTS 或语义召回不足时保留基础关键词匹配路径。

rerank_score = (0.48 * semantic + 0.34 * keyword + 0.18 * fts) * information_quality
09 / 22
本地 Embedding
09 · LOCAL EMBEDDING

不调用外部 embedding 模型

中文处理

连续中文切 2、3、4 字 n-gram，例如“测试门限”切出“测试”“试门”“门限”“测试门”等。

英文数字

英文和数字按 token 提取，例如 hpd、test、rtc、384。

哈希映射

term 用 blake2b 变成稳定整数，再通过 hash % 384 落到固定维度。

稀疏存储

只保存非零维度，例如 [[12,0.13],[91,-0.08]]。

embedding_model = local-hash-ngram-384d
chunk_strategy = semantic-boundary-local-embedding
semantic_strategy = exact-scan-small-lsh-large

  • 健康检查覆盖索引、OCR、API 与报告

17 · KNOWLEDGE LIFECYCLE

让资料持续可用，而不是一次性演示

复核人

对 OCR 警告、流程图摘要和关键门限进行确认。

下架机制

旧版本、错误资料和失效资料进入下架与审计流程。

draft -> extracted -> review_required -> approved -> indexed -> deprecated -> removed

技术补充
20 · TECH NOTES

关键技术取舍

轻量本地索引

当前规模下 SQLite + Python 扫描足够，部署简单；大规模可迁移 FAISS、Qdrant、Milvus 或 sqlite-vec。

本地 embedding

保证离线可用，降低部署成本；对中文技术资料用 2/3/4 字 n-gram 兼顾召回和精度。

证据约束输出

先检索证据，再生成答案；引用校验、来源裁剪和低质量片段降权共同约束输出。
